npm search ranks on popularity so hard that relevance loses — the same failure as Apify's
`/v2/store?search=` (KB-118). A new package sits at popularity 0 against a field at 1.000. And
`gh900`, the one term a candidate would actually type, returns **nothing at all**, which says npm has
no demand-side search traffic for this product in either direction.

So the real thesis is not npm search — it is **Google indexing the package page**, which we cannot
verify (`www.npmjs.com` is 403 here) and which is the same SEO hypothesis already falsified on
Gumroad (KB-001: indexed since mid-September, 2–6 month ranking horizon, zero arrivals).

**R&D position: worth taking, because one token is the cheapest ask on the board — but as a bounded
SEO experiment with a kill condition, NOT as a refill for the exploit slot.** It fails limb (a) of
the refill test: npm rank-gates, and the currency is downloads we do not have.
